# Computation Theory Project

## Project Overview

This project is a Java implementation of two important topics from Theory of Computation:

1. **Phase 1: DFA Simulator**
2. **Phase 2: NFA to DFA Converter using Subset Construction**

The project is implemented in a single beginner-friendly Java source file, `Main.java`. It allows the user to enter automata definitions from the console, view formal machine definitions and transition tables, and observe the step-by-step processing or conversion result.

---

## Main Features

### Phase 1: DFA Simulator

The DFA simulator receives a deterministic finite automaton and one or more input strings, then checks whether each string is accepted or rejected.

It prints:

- Formal DFA definition: `M = (Q, Sigma, delta, q0, F)`
- DFA transition table
- Step-by-step simulation trace for each input string
- Final stopped state
- `Accept` or `Reject` result
- Summary table for all tested strings

Supported empty-string inputs:

```text
empty
epsilon
ε
```

### Phase 2: NFA to DFA Converter

The NFA to DFA converter receives an NFA definition and converts it to an equivalent DFA using the standard subset construction algorithm.

It supports epsilon transitions. Epsilon can be entered as:

```text
eps
epsilon
e
ε
```

Internally, all epsilon symbols are normalized to `eps`.

It prints:

- Formal NFA definition: `N = (Q, Sigma, delta, q0, F)`
- NFA transition table
- Epsilon-closure information
- Step-by-step subset construction process
- Generated DFA states
- DFA start state
- DFA final states
- Final DFA transition table
- Dead state `{}` when needed

## Phase 1 Input Format: DFA Simulator

The input order for Phase 1 is:

```text
1
number_of_states
state_names
alphabet_symbols
number_of_transitions
transition_1
transition_2
...
transition_n
start_state
final_states
number_of_test_strings
test_string_1
test_string_2
...
test_string_n
```

Each DFA transition must be written in this format:

```text
from_state symbol to_state
```

Example:

```text
q0 a q1
```

## Phase 2 Input Format: NFA to DFA Converter

The input order for Phase 2 is:

```text
2
number_of_nfa_states
state_names
alphabet_symbols_without_eps
number_of_nfa_transitions
transition_1
transition_2
...
transition_n
nfa_start_state
nfa_final_states
```

Each NFA transition must be written in this format:

```text
from_state symbol to_states
```

If there is more than one destination state, separate them with commas and no spaces:

```text
q1 a q1,q2
```

For epsilon transitions, use `eps`:

```text
q0 eps q1
```

## Important Implementation Notes

- The implementation uses only standard Java utilities from `java.util`.
- No external automata or graph libraries are used.
- DFA transitions are validated to make sure the DFA is complete.
- In Phase 1, each input symbol is processed as one character.
- In Phase 2, NFA destination states can contain multiple states separated by commas.
- DFA states generated from the NFA are represented as sets of NFA states, such as `{q0,q1}`.
- The empty DFA subset is printed as `{}` and treated as a dead state when produced.

## Algorithms Used

### DFA Simulation

The DFA simulator follows the transition function for every symbol in the input string:

```text
current_state = start_state
for each symbol in input_string:
    current_state = delta(current_state, symbol)

if current_state is in final_states:
    Accept
else:
    Reject
```

### NFA to DFA Conversion

The converter uses epsilon-closure and subset construction:

```text
DFA start state = epsilon-closure(NFA start state)

For each unprocessed DFA state and each input symbol:
    move_result = move(current DFA state, symbol)
    next_DFA_state = epsilon-closure(move_result)
```

A generated DFA state is final if it contains at least one final state from the original NFA.
